## v0.0.6

v0.0.6 focuses on **controlled human-Agent closure, explainable operational observability, and
evidence-bound capability accumulation**. It further separates visible conversation, human decisions,
and Provider completeness in Channel and Kanban Agent; adds an opt-in OTLP/Operations plane; and
connects verified Autoresearch Learn results to a comparable, reversible Evolution lifecycle.

```text
Visible conversation / human decision
  -> EventLog + sidecar + controlled action
  -> existing Task / Gate / Delivery authority

Verified Learn Run
  -> immutable attempt + environment snapshot
  -> baseline / candidate / independent canary
  -> retained asset or revoked
```

This does not grant Task/Gate write authority to Web, monitoring systems, or Agents. Channel,
Observability, and Evolution continue to cooperate with the Kernel through events, artifacts, and
controlled actions; none becomes a second canonical state machine.

## Highlights

### 1. More controlled decisions and streaming replies in Channel and Kanban Agent

- Channel separates execution state from human attention as two read-only axes. While Agents are
  still responding, the page shows both active responders and pending decisions; it shows
  `Waiting for you` only when the execution scope is actually waiting for its Owner.
- `Operator Inbox -> Decisions` aggregates current Channel owner questions and Kanban Agent plan
  requests, but supplies only deep links back to the original conversation. Answers still travel
  through the existing controlled question/plan path.
- Visible Channel Markdown is separated from machine `channel_contribution` contracts. Kanban
  Agent `plan_request` and `action_proposal` blocks no longer flash as JSON in chat. Once detected,
  a Preparing state is shown until the canonical request replaces it with an actionable card.
- When Provider output is incomplete or lacks a required typed contract, Channel performs bounded
  continuation instead of treating the partial reply as a discussion conclusion. Complete raw replies,
  typed contracts, and artifacts remain available for audit and replay.

### 2. Provider and runtime observability as a separate, disableable operations plane

- Adds Provider capability state, managed Claude Code per-turn telemetry, redacted Runtime Logs,
  Operations summaries, low-cardinality Prometheus `/metrics`, an OTLP/HTTP synthetic-span exporter,
  and attention projections.
- The OTLP exporter sends an asynchronous read projection of EventLog using bounded batches, cursor,
  idempotency key, backoff, and sampling. Collector failures create diagnosable health/backlog data;
  they do not block EventWriter, Provider dispatch, or a Workflow.
- Delivery Graph, Run Graph, and Fanout DAG keep their existing data model and page ownership.
  Operations, Runtime Logs, and Events respectively address operational health, process diagnostics,
  and business causality.
- Endpoints, headers, and tokens are read only from environment variables. Prompts, replies, tool
  bodies, absolute paths, and high-cardinality business identifiers do not enter metric labels,
  Web read APIs, or exporter payloads.

### 3. Evidence-bound closure from Autoresearch to self-evolution

- A verified Learn Run enters an immutable campaign and evolution attempt only through the one typed
  deposition in its Run Archive. Ordinary Event text, chat projections, and unarchived replies cannot
  be promoted directly into a capability.
- Baseline/candidate comparisons freeze evaluator, Provider, toolchain, environment, sandbox, network,
  and credential-policy identity. Missing CLI, authentication, sealed evaluator, credential capability,
  or environment drift terminalizes with explicit evidence before calling a Provider; it is not recorded
  as a candidate quality loss or retried indefinitely.
- An asset must pass repeated trials, a sealed evaluator, an independent canary, and a receipt-bound
  state transition before reaching `active_retained`. Negative transfer, conflict, or insufficient
  evidence can revoke it.
- `auto_low_risk` may automatically retain only explicitly allowlisted `memory_entry`, `runbook`, and
  `regression_fixture` assets. `framework_code`, `workflow_config`, `provider_route`, and
  `tool_capability` remain proposal-only and require object-specific Owner approval and apply.

### 4. Bounded execution-policy evolution and developer-assistance skills

- For structured Provider/capability/context failures, Run Manager may select one bounded
  execution-route switch from a pre-approved static catalog for the same Task Owner. Its receipt binds
  Task, Run, checkpoint, and policy digest. It never invents Providers, models, permissions, or tool
  scopes dynamically.
- Adds `zf-find-simplifications` and `zf-record-browser-demo` skills. The former makes simplification
  proposals from consumer/protected-seam evidence; the latter records reproducible Docker Playwright
  frames, GIFs, and provenance for a browser workflow. Neither bypasses tests, Owner gates, or the
  release process.

## Delta from v0.0.5 to v0.0.6

From `v0.0.5` to `v0.0.6`:

- 20 single-parent commits;
- 257 files changed, with 29,932 additions and 1,265 deletions;
- the principal areas include 80 `src/zf/` files, 23 `web/src/` files, deterministic and
  real-Provider E2E coverage for Provider/OTLP and Evolution, Skills, and bilingual operations
  manuals.

These figures include tests, task records, reports, manuals, Skills, and binary documentation assets.
They are not a net-product-code claim. Release quality should be judged by controlled interaction,
event/evidence authority, observability isolation, and real-Provider validation.

## Upgrade Notes

1. **Keep the new planes disabled by default:** without `observability` or `runtime.evolution`
   configuration, this release does not start collectors, exporters, automatic adoption, or change an
   existing Project's behavior.
2. **Update dependencies and Web assets:** after deployment, run `uv sync --extra dev --extra web`,
   `npm --prefix web ci`, and `npm --prefix web run build`, then restart the runtime and Web Dashboard.
3. **Do not manually migrate business truth:** do not edit `events.jsonl`, Task/Feature stores,
   Channel sidecars, or `capabilities.json` to repair a page or adjust an asset state. Let the runtime
   and controlled commands rebuild new projections.
4. **Enable observability/evolution first in isolation:** use `/tmp/zf-<purpose>-<utc>/`, a controlled
   collector, and a minimal policy canary to verify environment preflight, redaction, token gating,
   backoff, comparison, and rollback before widening scope.
5. **Retain the Provider boundary:** managed native telemetry is currently claimed only for Claude Code
   headless/stream-json routes that support safe per-turn injection. Codex currently reports
   capability/probe state only; a ZaoFu synthetic OTLP span is not a Codex-native trace.

## Known Limitations

1. **Evolution is a partial capability:** it is not model training and does not automatically rewrite
   source, configuration, Skills, or mainline. High-risk assets still require a proposal, Owner approval,
   and controlled apply.
2. **Context and ordinary Memory are not a complete historical-replay system:** ordinary Memory's
   `max_days` remains metadata rather than a strict per-entry expiry/applicability gate. Long-term reuse
   requires inspecting retained-asset scope, evidence, conflict, and usage outcome.
3. **External telemetry rollout needs an independent canary:** fake collector and managed-route tests
   do not prove that a particular collector, Claude/Codex version, or host network will complete a
   telemetry protocol end to end.
4. **The public projection retains 22 classified deterministic baseline/host reds:** ten Codex hook
   hash version sensors, two fixed fake-path host preflights, nine tests that reference files absent
   from the public projection, and one sim1 `base_commit` mismatch. Every node reproduced on detached
   `dev@ffe4d43`; release validation neither rewrote hash/version baselines nor restored private files
   explicitly excluded by the manifest.
5. **npm development tooling retains audit findings:** the production-dependency audit reports zero
   high and one low; the full audit's three high findings are in Babel/PostCSS/Vite/nanoid development
   build paths. This release does not automatically run `npm audit fix` and expand lockfile scope.
6. **Developer Preview:** Web/API, event schemas, Provider capability, and interaction contracts may
   still change incompatibly before 1.0.

## Summary

v0.0.6 does not replace engineering constraints with more Agent autonomy. It makes visible answers,
human decisions, and machine contracts in multi-Agent conversations clearer; makes runtime health
observable without changing delivery truth; and accumulates verified experience as reusable capability
within explicit evaluation, environment, and rollback boundaries.
