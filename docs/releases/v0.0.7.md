## v0.0.7 版本

v0.0.7 聚焦 **浏览器内真实 Coding Agent PTY、可恢复的多客户端控制，以及与 Workflow
预算隔离的逐 Terminal 用量证据**，同时简化 Delivery、Trace 和 Loop 的日常诊断面。用户可以
在 Dashboard 中启动或恢复真实 Codex、Claude Code 等原生 TUI；ZaoFu 负责 Project、鉴权、
Session 与用量边界，Herdr 负责真实 PTY、终端状态和 controller 仲裁。

```text
当前 Project effective Provider 配置
  -> token-gated Web Terminal action
  -> Project-scoped Terminal Session + one-time WebSocket ticket
  -> Herdr named session / PTY
  -> real Coding Agent CLI

Terminal bytes / screen state
  -> ephemeral interaction plane
  -/> Task / Workflow / Gate canonical truth
```

> **默认行为变化：** Dashboard host 的 `runtime.web_terminal.enabled` 现在默认 `true`，会开放
> Project-scoped、bounded 的只读投影与能力探测；所有 mutation 和 attachment ticket 签发仍需
> 鉴权。它不会自动安装 Herdr、启动 Provider、扩大目标 Project 权限或把 Terminal 内容写成
> 业务事实；依赖未通过资格检查时返回 typed unavailable。宿主可显式设置 `false` 退出；直接
> 禁用只撤下 Web capability，不会终止已经运行的 CLI。

## 发布亮点

### 1. Dashboard 内的真实 Coding Agent Terminal

- Dashboard 顶栏提供按需加载的 Terminal；首次打开才加载 xterm.js 与对应资源，支持默认全屏、
  可调高度的原生底部 Dock、light/dark 主题和窄屏布局。
- 一个 Project 可建立多个彼此隔离的 Terminal Session。每个 Tab 对应独立 PTY、Provider、
  generation 与用量身份；切换 Tab 不卸载 xterm、不重连 WebSocket，也不会混合输出。
- New Session 菜单从当前 Project 初始化后的 effective orchestrator/roles backend 派生。
  single Project 只显示自己的 Provider，mixed Project 才显示多个 Provider；不再维护一份
  Terminal 专用 allowlist。
- Session 默认使用 `Codex 1`、`Claude Code 1` 等语义名称；受鉴权 Rename 先更新 Herdr tab
  label，成功后在 registry 锁内原子持久化展示名称，不改变 PTY 或用量身份。
- 关闭 Drawer、关闭浏览器或关闭 UI Tab 只 detach；只有显式 `Stop CLI` 才终止对应 Session。

### 2. Observe、Control、Take over 与断线恢复

- 同一个 Terminal Session 支持多个 observer，但同时只有一个 controller。普通查看使用
  Observe，需要输入时使用 Control；替换失联控制端必须显式执行 Take over，并受 host policy、
  mutation auth 与 receipt 约束。
- WebSocket attach 使用一次性、短时、绑定 Project/Session/mode 的 ticket；连接按 full frame
  建立基线，再消费连续 seq 的 delta。慢客户端只影响自身；有界队列溢出时关闭该慢连接，
  客户端重连后从新的 full frame 恢复，不拖住 PTY 或其他客户端。
- 浏览器刷新、Drawer reopen 和客户端网络断开后，可重新 attach 同一 Herdr Session 并恢复完整
  屏幕历史。分享演示验证了控制端离线时 Codex 继续运行以及全新客户端恢复，但不把这项证据
  扩张为 Dashboard、Herdr 或宿主机宕机恢复保证。
- Project registry、cwd、Herdr named session 和 Terminal registry 保持 Project 隔离；过期的
  浏览器 Project 选择会回落到当前 Workspace 中有效的 Project，不继续向已删除对象发请求。

### 3. 逐 Tab 用量、成本与 Provider 证据

- Claude Code 与 Codex 的结构化 transcript usage 绑定不可变的
  `project_id + terminal_session_id + generation + provider_session_id`。可变 Tab 名只用于展示，
  Rename、刷新、重复 reconcile 或多浏览器 attach 不会重复计费或串账。
- Terminal 用量写入独立 `terminal-cost.jsonl`，Agents 页以 `Interactive Terminals` 分行展示
  Provider、model、context、tokens、cost 与 precision。它不进入 Workflow `cost.jsonl`，也不
  影响 Task/Run budget gate。
- 缺少唯一 Provider session、结构化 usage 或合格 reader 时，页面显示 `awaiting usage`、
  `unsupported` 或不可用，而不是伪造 `$0`。
- 当前一台 Linux x86_64 host 的 qualification 已验证 Herdr `0.8.2` 与 Codex CLI `0.148.0` 的真实 TUI、`/status`、
  交互、按 Tab usage/cost 和显式 Stop。Claude Code `2.1.233` 已验证真实 TUI 启动与 blocked
  session 保留，但登录返回 `Login expired`，因此 Claude usage/cost 仍是 credential-blocked；
  OpenCode/Pi 尚未完成真实资格与 usage reader 签收。

### 4. 明确的宿主安全与权威边界

- `runtime.web_terminal.enabled` 默认 `true`，也可在 Dashboard host 的 `zf.yaml` 中显式设为
  `false`。Host policy 决定 backend、Herdr binary、最低版本、takeover 与资源上限；目标 Project
  不能自行扩大这些权限。
- create、rename、attach、takeover、stop 和 reconcile 都必须先解析已注册 Project，并通过现有
  token/passcode/trusted-session mutation auth。浏览器不能提交任意 executable、cwd、argv 或
  环境变量。
- 当前 action token/passcode trusted session 的 mutation 信任域是整个 Dashboard instance，
  不是 per-Project ACL；Project-scoped 表示 Session、registry、cwd 和 receipt 的隔离，不代表
  每个 Project 拥有独立授权。互不信任的 Project 或用户应隔离到不同 OS user、container、VM
  或 host。
- Provider 子进程环境会剥离名称带 `TOKEN`、`PASSCODE`、`SECRET` 或 `ENCRYPT_KEY` marker 的
  `ZF_*` 控制平面变量，以及列明的 Claude/Codex 父 session/thread、`CODEX_CI` 和
  nested-entrypoint 控制变量；Provider 自身正常 credential/env 仍按宿主策略保留。
- Terminal 字节、ANSI 屏幕和 TUI 文本不写入 EventLog、Task、Workflow 或 required artifact，
  也不会自动生成 Trace/Span、Delivery、Loop 或 Graph 事实，不能通过 screen scraping 推进
  Kernel 状态。Provider 自己的 native transcript 仍可存在；ZaoFu usage reader 会逐行解析相关
  JSONL，但只提取和投影 usage、model、timestamp 与 identity 字段，不会把 prompt、回复、tool
  body 或终端字符流持久化到 Terminal 用量账本或投影至 Web/API。Herdr named session 提供 PTY
  能力，不是 OS sandbox，也不是第二套 ZaoFu orchestration state machine。

### 5. 更聚焦的 Delivery、Trace 与 Loop 诊断面

- Delivery work、lifecycle、run 和 graph 投影移到服务端聚合，Web 按当前视图加载需要的数据，
  降低重复派生和大页面首屏成本。
- 独立 Traces 页面提供 span tree、waterfall 和关联详情；Loop 与 Run regression action 使用明确
  的资源与刷新策略，减少重复面板和隐式轮询。
- 这次界面简化不改变 EventLog、Store、Artifact 或 Gate 权威；页面仍是 read-oriented
  projection，受控 mutation 继续走既有 action path。

## 升级说明

1. **同步版本元数据**：Python、CLI、Web 和 lockfile 已统一为 `0.0.7`；部署或构建缓存中若仍
   显示旧版本，应先重新同步依赖并重建静态资源。
2. **更新依赖与静态资源**：执行 `uv sync --extra dev --extra web`、`npm --prefix web ci`、
   `npm --prefix web run build`，再重启 ZaoFu Web。
3. **安装并固定 Herdr**：安装 Herdr `>=0.8.0`，记录实际 release、binary SHA256 和 host
   qualification；不要在运行时自动下载或无审计升级。
4. **确认默认开启策略**：Web Terminal 默认开启，但依赖缺失只会呈现 unavailable。若宿主不应
   暴露 Terminal，先在 capability 仍启用时精确 Stop 受影响 Session，再配置
   `runtime.web_terminal.enabled: false` 并重启；直接禁用不会终止已运行 CLI。
5. **保护远程入口**：远程部署使用长期 action token 或 passcode session，并放在可信网络与
   HTTPS 后；不要把 Herdr named session 当作多租户 OS sandbox。
6. **分别验证 Provider**：安装并登录当前 Project effective backend 对应的 CLI。Codex receipt
   不能代替 Claude Code、OpenCode 或 Pi 的独立资格验证。
7. **保持真相分层**：Terminal 适合交互式 Coding Agent TUI；需要推进 Task/Workflow 时，仍使用
   Event、artifact 与 controlled action，不从终端屏幕文本推断完成或 verdict。

## 已知限制

1. **能力状态仍为 partial**：当前签收的是一台 Linux x86_64 host 上的核心能力与 Codex
   切片；macOS/Windows、完整 crash/IME/长输出矩阵以及更多宿主组合尚未 qualification。
2. **Provider 资格不对称**：一台 Linux x86_64 host 上的 Codex startup/interaction/usage 切片已签收；Claude usage 受登录态阻断；
   OpenCode/Pi 尚无本版本的真实 Provider 与结构化 usage 证据。
3. **恢复边界有限**：浏览器或设备断线后可以重连 Herdr Session，但不承诺宿主机 reboot 后保持
   同一个物理 PTY；分享视频也不是 Dashboard/Herdr crash-recovery 证明。
4. **Terminal 不是持久 transcript 系统**：默认不把完整终端字符流写入 EventLog 或 artifact；
   需要审计的业务结果必须通过现有受控路径留下 evidence。
5. **Usage 取决于 Provider 结构化证据**：不支持、未登录或无法唯一绑定 session 时会明确显示
   unavailable/unsupported；当前 cost 是基于结构化 usage 与 Pricing Catalog 的投影，不是
   Provider invoice，也不能把无证据解释为真实消耗为零。
6. **公开投影仍有 21 个已分类基线/宿主红项**：包括 10 个 Codex hook hash sensor、2 个固定
   假路径 host preflight、8 个引用公开投影缺失文件的测试，以及 1 个 SIM1 immutable
   `base_commit` 断言。相同 21 个节点已在 detached `v0.0.6@a814a79` 全部原样复现；发布验证
   未改写 hash/version 基线，也没有把精确分类后的闭包称为全量全绿。
7. **Developer Preview**：Web/API、Terminal 协议、Provider capability 和交互合同在 1.0 前
   仍可能发生不兼容变更。

## 总结

v0.0.7 把真实 Coding Agent TUI 带进 Dashboard，但没有把终端升级为业务真相或第二套编排器。
它以明确的 Project、鉴权、Session、controller、Provider 和 usage 边界，让浏览器 Terminal
具备可操作、可恢复、可诊断的工程基础。
