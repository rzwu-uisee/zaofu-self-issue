## Overview

v0.0.4 packages four groups of runtime work after v0.0.3: Task Pipeline / Orchestrator Agent control,
Provider cost and long-horizon recovery, Task Contract Authority, and Kanban Agent turn-level
observability.

This release remains a Developer Preview. Agents, Skills, and Prompts own semantic judgment. The
Kernel owns mechanical boundaries such as schema, currentness, CAS, leases, dispatch, evidence
presence, and external effects.

## Highlights

### 1. Task Pipeline and Orchestrator Agent Control

- Added the Task Pipeline orchestration runtime, Task workspaces, Stage Workers,
  dispatch/recovery/rework/terminal paths, and Task Pipeline Web projections.
- Added Orchestrator Agent admission, briefing, typed decisions, Plan adoption, semantic failure, and
  controlled operation modules.
- Added v4 canary and OA pilot controller profiles. Stable production paths remain controlled and do
  not switch implicitly.

### 2. Provider Cost, Budgets, and Long-Horizon Recovery

- Added a pricing catalog, billing calculator, provider usage reconciliation, and Web cost projection.
- Hard budgets now fail closed for unpriced usage instead of dispatching unknown cost as zero-cost work.
- Added Long-Run Truth, Recovery Cases, manual evidence gates, retention inventory, self-repair
  lifecycle, and no-progress convergence paths.

### 3. Task Contract Authority

- Added the Task authority schema, TaskStore CAS, and `TaskContractAuthorityService`.
- TaskAttempt, dispatch, Impl/Verify, Candidate, Judge, and terminal closure now bind to the current
  execution target. Stale writes, stale results, and old verification receipts fail closed.
- Added the task contract authority doctor and real Provider A/B support script.

### 4. Kanban Agent Turn Observability

- Added Kanban Agent turn ephemeral deltas, first-output/context/provider timing, and terminal timing
  payloads.
- Added a Web Kanban interaction policy so stale UI selections do not rewrite the Plan backend binding.
- Workflow inspection, Task projections, and the Orchestrator panel expose clearer runtime-boundary
  readback.

## Upgrade Notes

1. Reinstall dependencies from the release checkout and confirm the version:

```bash
uv sync --extra dev --extra web
npm --prefix web ci
uv run zf --version
```

Expected:

```text
zf 0.0.4
```

2. Do not switch pilot execution paths implicitly:

- Task Pipeline v4 should still be enabled through an explicit canary, shadow, or profile.
- Orchestrator Agent semantic control should still be enabled through an allowlisted pilot.
- Profile changes should start a fresh Run while preserving prior artifacts, attempts, and recovery
  evidence.

3. Validate the pricing catalog before enabling cost budgets:

```bash
uv run zf cost
uv run zf cost --by-instance
uv run zf cost --by-backend
```

## Known Limitations

- During Developer Preview, Python APIs, Web APIs, event schemas, Controller profiles, and parts of the
  CLI may still change incompatibly before 1.0.
- Task Pipeline v4 and Orchestrator Agent semantic control remain controlled pilots, not unconditional
  defaults.
- Real Provider, real Feishu, and browser validation depend on the target tenant, credentials, and
  environment, and remain operator-owned.
- Retention inventory is currently read-only/planning behavior and does not delete runtime evidence
  automatically.
