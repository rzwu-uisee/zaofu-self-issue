## v0.0.5 版本

v0.0.5 聚焦 **Coding Agent 对话面的可读性、完整性和首屏成本**。Channel Group 与 Kanban
Agent 继续保留各自的业务控制，但共享正文、Plan、AskUserQuestion、Tool、Artifact、流式状态
和滚动行为。Provider 的人类可读 Markdown 与机器可读合同被投影为不同层次，主时间线不再
暴露原始 JSON、重复 preview 或 sidecar 截断提示。

```text
Provider reply
  -> immutable sidecar body + structured contribution
  -> bounded server-side conversation projection
  -> shared AgentSessionTimeline
  -> readable Markdown + compact semantic cards
  -> lazy diagnostics / artifact details on demand
```

这不是一套新的 Channel canonical store。事件、sidecar 与现有状态所有权保持不变；新增能力
属于可重建的 Web 读投影和共享会话呈现层。

## 发布亮点

### 1. Channel 与 Kanban Agent 共享 Conversation Surface

- 两个入口复用 `AgentSessionTimeline`、Markdown、Plan、AskUserQuestion、Tool 和 Artifact
  renderer，不再分别维护相互漂移的聊天展示逻辑。
- active turn 与 settled turn 使用一致的视觉和状态合同；待处理交互保持可操作，已完成交互
  收敛为紧凑 receipt。
- Kanban Agent 桌面 dock 提升到适合长 Markdown 的宽度，小屏退化为近全屏，并保留
  fullscreen、collapse 和 composer 行为。

### 2. 人类可读回复与结构化合同分层

- 服务端输出 `display_text + structured_contribution`，正文只显示 Markdown；Findings、Risks、
  Contradictions 和 Questions 以紧凑语义卡片呈现，并保留 immutable artifact ref。
- 原始 `channel_contribution` JSON、重复 preview 和 `sidecar body truncated` 不再污染主时间线。
- 修复合同后文本丢失：解析器只移除已解码的 fenced/plain JSON 合同区间，保留合同前后的
  人类文本。历史 sidecar 无需重新生成即可通过新投影恢复完整正文。

### 3. 轻量 Conversation API 与历史分页

- 新增 `GET /api/projects/<project>/channels/<channel>/conversation`，默认返回最近 50 条、最多
  100 条消息，并通过 `before`、`has_more` 和 `next_before` 稳定加载更早历史。
- 首屏只携带当前消息相关的有界 reply/provider run 元数据与结构化摘要，不再重复返回完整
  transcript、linked events 和 context packs。
- 同一真实 Channel 的响应从 `947,584B` 降至 `97,076B`，下降约 `89.8%`；120 条分页测试
  无重复、无缺失。

### 4. Diagnostics 按需加载与当前 Channel 范围

- Chat 首屏只请求 summary + conversation；用户打开 Details 后才请求完整 Channel detail。
- Reply Flow、Context Packs、linked events 和 provider parts 收敛到默认折叠的 Diagnostics，
  并具备 loading、error 和 empty 状态。
- Details 删除与当前群组无关的全项目 Workflow Roles；角色发现继续由 Add Agent 承担。
- 独立 request gate 防止快速切换 Channel 时旧响应覆盖新选择。

### 5. 长历史、流式回复和滚动稳定性

- 同一 active run 持续增长同一条回复；实时 refresh 会合并已加载历史窗口。
- 用户向上阅读时不会被自动拉回底部，新 delta 通过 `New messages` 提示回到底部。
- prepend 更早历史时保持 scroll anchor；只有 `history_clear_event_id` 改变才重置窗口。
- settled turn 使用 `content-visibility` 降低长历史布局成本，active turn 保持立即可见。

## 从 v0.0.4 到 v0.0.5 草案

从 `v0.0.4` 到草案来源提交 `6310a5d`：

- 合并了 conversation UX 改动，并在本轮公开分支修正了同步时混入的 public-export 残留；
- 主要变化集中在 Channel conversation projection、轻量 conversation API、共享
  AgentSessionTimeline、Channel/Kanban 前端交互和对应 Python/Web 回归测试；
- 本草案不声明正式 v0.0.5 release，也不修改 canonical runtime state。

这些统计包含测试、任务记录和设计文档，不等同于净产品代码量。发布质量以回复完整性、
分页一致性、交互回归和真实 Provider/browser 证据为准。

## 升级说明

1. **无需迁移 canonical state**：本版本新增可重建的 conversation read projection，继续读取
   现有 EventLog、Channel 状态和 sidecar。
2. **重新构建 Web 资源**：部署更新后执行 `npm --prefix web ci` 和
   `npm --prefix web run build`，再重启 Web Dashboard。
3. **保留完整 detail API**：普通 Chat 使用轻量 endpoint；Details、诊断和既有集成仍可读取
   完整 Channel detail。
4. **保留 sidecar**：不要因为主时间线隐藏机器合同而删除 contribution/body sidecar；它们仍是
   结构化事实、审计和重新投影的来源。

## 已知限制与发布阻断项

1. **版本元数据未升级到 v0.0.5**：Python 与 Web 仍为 `0.0.4`；正式发布前必须统一所有版本
   入口并从最终提交重新验证。
2. **服务端扫描成本尚未消除**：conversation endpoint 当前仍先通过 `project_channel()` 重建
   内存投影再裁剪 response。本版显著降低网络、JSON parse 和 React commit 成本，但不是持久化
   conversation read model。
3. **Provider 输出上限仍存在**：本版修复 ZaoFu 投影丢失，不改变 Codex、Claude Code、
   OpenCode 或其他 Provider 的模型 token/output 限制。
4. **不是完整 release matrix**：草案来源提交已执行影响闭包、Web 和真实 Codex browser 测试，
   但尚未在同一候选上执行全量 pytest、全部 Provider、Feishu 与所有宿主能力测试。
5. **Developer Preview**：Web/API、事件 schema 和部分交互合同在 1.0 前仍可能不兼容变化。

## 总结

v0.0.5 把 Channel Group 与 Kanban Agent 从“能显示 Provider 输出”推进到“使用同一会话合同，
以有界成本完整、可读、可回读地显示 Provider 输出”。机器合同和诊断证据仍被保留，但不再
支配普通聊天界面；长回复、长历史和实时增量也具有明确的完整性与滚动行为。
