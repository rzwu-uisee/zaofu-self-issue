## v0.0.5

v0.0.5 focuses on **readability, completeness, and first-load cost for Coding Agent conversations**.
Channel Group and Kanban Agent keep their distinct product controls while sharing message bodies,
Plans, AskUserQuestion, Tools, Artifacts, streaming state, and scrolling behavior. Human-readable
Provider Markdown and machine-readable contracts are projected into separate layers, so raw JSON,
duplicate previews, and sidecar truncation notices no longer dominate the main timeline.

```text
Provider reply
  -> immutable sidecar body + structured contribution
  -> bounded server-side conversation projection
  -> shared AgentSessionTimeline
  -> readable Markdown + compact semantic cards
  -> lazy diagnostics / artifact details on demand
```

This is not a second canonical Channel store. Event, sidecar, and state authority remain unchanged;
the new behavior is a rebuildable Web read projection and shared conversation presentation layer.

## Highlights

### 1. Shared Conversation Surface for Channel and Kanban Agent

- Both surfaces reuse `AgentSessionTimeline` and the same Markdown, Plan, AskUserQuestion, Tool, and
  Artifact renderers instead of evolving separate chat implementations.
- Active and settled turns follow one visual and state contract. Pending interactions remain actionable,
  while completed interactions collapse into compact receipts.
- The Kanban Agent desktop dock is wider for long Markdown; small screens fall back to a near-fullscreen
  layout while preserving fullscreen, collapse, and composer behavior.

### 2. Human-Readable Replies Separated from Typed Contracts

- The server projects `display_text + structured_contribution`. Markdown remains the primary body;
  Findings, Risks, Contradictions, and Questions become compact semantic cards with immutable refs.
- Raw `channel_contribution` JSON, duplicate previews, and `sidecar body truncated` notices are hidden
  from the main timeline.
- Contract-tail content loss is fixed: the parser removes only the decoded fenced/plain JSON range and
  preserves human text before and after it. Existing sidecars recover through reprojection without a
  Provider rerun.

### 3. Lightweight Conversation API and History Pagination

- `GET /api/projects/<project>/channels/<channel>/conversation` returns the latest 50 messages by
  default, up to 100, with stable `before`, `has_more`, and `next_before` pagination.
- Initial chat payloads include only bounded reply/Provider run metadata and structured summaries for
  the selected messages, not full transcripts, linked events, or context packs.
- On the same real Channel, response size fell from `947,584B` to `97,076B`, about `89.8%`; a 120-message
  pagination test reported neither duplicates nor gaps.

### 4. Lazy Diagnostics and Current-Channel Scope

- Initial Chat load requests summary plus conversation only. Full Channel detail loads when the operator
  opens Details.
- Reply Flow, Context Packs, linked events, and Provider parts move into collapsed Diagnostics with
  loading, error, and empty states.
- Project-wide Workflow Roles were removed from Channel Details; role discovery remains in Add Agent.
- An independent request gate prevents a stale response from replacing the newly selected Channel.

### 5. Stable Long History, Streaming, and Scrolling

- One active run grows one reply, while live refresh merges the already-loaded history window.
- When the reader scrolls away from the bottom, new deltas show a `New messages` affordance instead of
  stealing the scroll position.
- Prepending older messages preserves the scroll anchor; only a changed `history_clear_event_id` resets
  the window.
- Settled turns use `content-visibility` to reduce layout cost, while active turns remain immediately
  visible.

## Upgrade Notes

1. **No canonical-state migration is required:** the new conversation read projection is rebuildable
   from the existing EventLog, Channel state, and sidecars.
2. **Rebuild Web assets:** run `npm --prefix web ci` and `npm --prefix web run build`, then restart the
   Web Dashboard.
3. **Retain the full detail API:** normal Chat uses the lightweight endpoint; Details, diagnostics, and
   existing integrations can still read full Channel detail.
4. **Retain sidecars:** hiding machine contracts from the main timeline does not make contribution/body
   sidecars disposable. They remain sources for structured facts, audit, and reprojection.

## Known Limitations and Release Blockers

1. **Version metadata is not aligned:** Python and Web remain `0.0.2`, and v0.0.3/v0.0.4 have no public
   tags. Resolve the version sequence and align every version entry before release.
2. **Server scan cost remains:** the conversation endpoint currently rebuilds `project_channel()` in
   memory before trimming the response. This release significantly reduces network, JSON parse, and
   React commit cost, but it is not yet a persistent conversation read model.
3. **Provider output limits remain:** this release fixes ZaoFu projection loss; it does not change model
   token/output limits in Codex, Claude Code, OpenCode, or other Providers.
4. **This is not a full release matrix:** the candidate passed impact-closure, Web, and real Codex
   browser tests, but not full pytest, every Provider, Feishu, and every host-capability tier in one run.
5. **Developer Preview:** Web/API, event schemas, and interaction contracts may still change
   incompatibly before 1.0.

## Existing Validation Evidence

- The candidate branch and merged `dev` both passed the impact closure: `637 passed, 1 deselected`,
  with Web typecheck and all unit tests passing.
- Pre-merge and post-merge sentinel gates both reported `51 passed`.
- Docker Playwright layout and interaction checks passed. A 55-message Channel retained its scroll
  anchor; the Kanban Agent dock measured `633.6px` at 1440px and did not overflow at a 390px viewport.
- Real Codex ran two Channel Group rounds and two Kanban Agent rounds. The largest response was 4,602
  characters / 12,164 bytes; all four start/end markers survived reload, with no raw contract,
  truncation marker, or browser error.
- Regression tests cover contracts in the middle of fenced/plain JSON replies; reprojection restores
  trailing prose from an existing sidecar.

## Summary

v0.0.5 advances Channel Group and Kanban Agent from “displaying Provider output” to “displaying it
completely, readably, and at bounded cost under one conversation contract.” Machine contracts and
diagnostic evidence remain durable without dominating ordinary chat, while long replies, long history,
and live deltas now have explicit completeness and scrolling behavior.
